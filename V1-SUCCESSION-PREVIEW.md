inside the Discord tools. Cutover therefore requires an atomic same-filesystem
swap:

1. verify v1 is still stopped and its live head still equals the frozen source

2. verify the candidate is still unopened and matches the plan;
3. rename the original v1 habitat aside without deleting it;
4. rename the candidate to the original habitat path;
5. apply the separately approved effect grants; and
6. start the exact installed v2 release.

first v2 perspective or world contact is retained, v1 and v2 are divergent
descendants. Returning to v1 would be a lineage choice, not a software rollback,
and no automatic merge is claimed.
